## Context

`--sandbox docker` has never run an agent. A container on `--network none` or on an
internal network has no route to `api.anthropic.com`, so `claude -p` inside it cannot
reach the model; and the symptom is a 15-retry storm that ends at `AGENT_TIMEOUT_S`,
indistinguishable from an agent that is merely slow. Measured in the grill, not reasoned
to: `.edad/grills/sandbox-tier.md`, second and third passes.

The way out is measured too. The CLI sends `CONNECT api.anthropic.com:443` in plaintext
before any TLS, honours `HTTPS_PROXY`, and with
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` dials that one host and nothing else. So a
proxy that reads the `CONNECT` line, matches the host against a one-entry allowlist, and
either splices bytes or refuses gives the agent the model and nothing else — with no
interception, no certificate, no decryption. The grill's third pass ran exactly that,
by hand, through a ~60-line prototype: a valid `setup-token` from a DNS-less internal net
produced `ok` in 4s.

This ticket is that prototype made permanent, and the plumbing that starts it. It is
its own ticket because the allowlist *is* the security boundary of the tier (D13, D14):
it should be reviewable on its own, in a file small enough to read in one screen, with
nothing docker-shaped beside it.

## Goal

Three files exist and do what the frozen test says.

`edad/egress_proxy.py` is the daemon. Given a socket, it reads the request head, and:
a `CONNECT` to a host in the allowlist is answered `200` and spliced to the upstream,
bytes passing both ways until either side hangs up; a `CONNECT` to any other host — a
raw IP included — is answered `403` and closed, with **no upstream connection
attempted**; anything that is not a `CONNECT` is answered with a `4xx` and closed, again
with no dial. The allowlist is exactly `{"api.anthropic.com"}`, immutable, and is the
parameter the daemon matches against rather than a constant nothing reads.

`edad/egress.py` is the lifecycle. The proxy for a network is named
`edad-egress-<network>`, deterministically, so a queue and every child it spawns compute
the same name from the same flag. `ensure_egress_proxy` starts one on `bridge` and then
`docker network connect`s the internal net — the one ordering docker supports, since a
container *started* on an internal net can never reach out — creates only when absent,
and reports whether it did, which is what lets whoever created it be the one who removes
it. `remove_egress_proxy` tears down by name.

`Dockerfile.egress` is the image: the checked-in daemon and an interpreter, nothing
fetched at build time. The harness does not build it, as it does not build the agent
image; a missing image is refused naming the build command.

## Required interface

All names are pinned by `tests/test_egress_proxy.py`; read it before writing anything.

**`edad/egress_proxy.py`** — stdlib only. Nothing from `edad` beyond itself: the image
copies this one file and `edad/__init__.py`, and an import of anything else breaks the
container at start.

- `ALLOWLIST: frozenset[str]` — `frozenset({"api.anthropic.com"})`. Hosts only, matched
  as strings against the `CONNECT` target's host part. No DNS, no normalisation beyond
  what the CLI actually sends (a bare hostname, measured).
- `PORT: int` — the port the daemon listens on, and the port `edad.egress.proxy_url`
  points the agent at. The daemon's own constant; `egress.py` imports it.
- `dial(host: str, port: int) -> socket.socket` — the default upstream connection, and
  the only place the daemon reaches out.
- `handle(client: socket.socket, *, allowlist=ALLOWLIST, dial=dial) -> None` — one
  connection, start to finish. The frozen test calls it directly against one end of a
  `socketpair`, in a thread, with `dial` replaced by a stand-in that records the target
  and hands back one end of a second pair. So: read the head; not `CONNECT` → send a
  `4xx` status line and close; host not in `allowlist` → send `HTTP/1.1 403 ...` and
  close, and `dial` must not have been called; otherwise `dial(host, port)`, send
  `HTTP/1.1 200 ...`, and splice until EOF on either side, propagating the hangup to the
  other side as a write shutdown. Close the client socket on every path. A `dial` that
  raises `OSError` is answered with a `5xx`, not a traceback.
- `serve(listener: socket.socket, *, allowlist=ALLOWLIST, dial=dial) -> None` — accept
  loop, one `handle` per connection. `main()` binds `0.0.0.0:PORT` and serves; the
  `if __name__ == "__main__"` block is what `Dockerfile.egress`'s `CMD` reaches.

Keep it to one screen. The grill's prototype was ~60 lines; the probe implementation
that took the frozen test green was 101 with its docstring. A daemon that needs a
config language, a class hierarchy or a third module has grown past what an auditor can
verify by reading, which is the property D14 was chosen for.

**`edad/egress.py`** — the docker plumbing, apart from the daemon.

- `IMAGE: str` — `"edad-egress:latest"`.
- `BUILD_COMMAND: str` — the literal command that builds it, naming `Dockerfile.egress`
  and `IMAGE`. Refusals quote it.
- `class EgressError(Exception)` — the proxy could not be ensured. Raised here, never
  `Abort` or `Refusal`: both entry points import this module, and each translates it to
  its own refusal (T016, T013).
- `docker(args: list[str]) -> tuple[int, str] | None` — runs `["docker", *args]` and
  returns `(returncode, stripped stdout)`, or `None` when docker could not be run at
  all (`OSError`, timeout). The **only** thing in this module that shells out, and a
  module-level name because the frozen test replaces it; nothing else here may call
  `subprocess`.
- `proxy_name(network: str) -> str` — `f"edad-egress-{network}"`.
- `proxy_url(network: str) -> str` — `f"http://{proxy_name(network)}:{PORT}"`, what
  `HTTPS_PROXY` in the agent container is set to (T016).
- `ensure_egress_proxy(network: str) -> bool` — in this order: `docker container
  inspect <name>` (`None` → `EgressError`, docker is not there; exit 0 → present, return
  `False` having run nothing else); `docker image inspect IMAGE` (non-zero → `EgressError`
  whose message contains `BUILD_COMMAND`, and no `run` is attempted); `docker run -d --rm
  --name <name> --network bridge IMAGE` — exactly one `--network`, and the internal
  net's name appears nowhere in this argv; then `docker network connect <network>
  <name>`; return `True`. A failed `run` or `connect` raises `EgressError`; a failed
  `connect` removes the half-made container first, so a retry does not find a proxy
  with no route to the agent.
- `remove_egress_proxy(network: str) -> None` — one `docker rm -f <name>` (or
  `container rm -f`); the name is the last element. Its result is ignored: removing what
  is not there is not an error.

**`Dockerfile.egress`** — `FROM python:3.12-slim`, a `COPY` line naming
`edad/egress_proxy.py` (with `edad/__init__.py`, so `-m edad.egress_proxy` resolves), a
`CMD` or `ENTRYPOINT` that runs it. No `pip install`, `apt-get`, `curl`, `wget` or `npm`:
the frozen test refuses each by substring, because a boundary that depends on what a
registry served on build day is not one file. Comment the build command at the top; it
is the one operators will need.

## Settled here

**A missing proxy image is refused, not built.** The spec left this deferred with a
spec-stage default; this ticket takes the default, and
`test_ensure_refuses_when_the_image_is_absent_naming_the_build_command` pins it. Parity
with the agent image, which the harness also does not build, and with D18's shape:
"absent" gets a plain message naming the fix rather than the failure `docker run` would
produce a step later.

**Present means present, not healthy.** `ensure` finds a proxy by `container inspect`
succeeding and leaves it. A container that exists but is dead is caught one step later
by T016's permit probe, which is the check designed to notice a dead proxy (D16); a
second liveness check here would be the inspection-only check D16 rejected, one layer
down. `--rm` on the `run` is what keeps this honest: a daemon that crashes takes its
container with it, so the next `ensure` finds nothing and starts a fresh one rather than
finding a stopped shell with the right name.

**Two standalone sessions on one network race on `ensure`.** Carried from the spec's
deferred list as a sentence, not a design: the queue is single-owner and safe; two
concurrent standalone sessions can both see "absent" and both `run`, and the second
`--name` collision fails as an `EgressError`. Acceptable for now, and named so nobody
reads the lifecycle as concurrency-safe.

## Out of scope

- **Pointing the agent at the proxy, and probing it** — `HTTPS_PROXY`,
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, the egress probe, the refuse/permit probes,
  the token refusal: **T016**, all of it in `edad/session.py`. This ticket ships nothing
  that any entry point calls yet; that is why it has no blockers and is first.
- **The session and queue halves of D17** — who calls `ensure` and `remove`, and when:
  **T016** (standalone session) and **T013** (queue).
- **The live proof** — the real image, dual-homed, permitting `api.anthropic.com` and
  refusing another host against actual docker: `docker_tests/test_properties.py`, hand-
  written and opt-in (D7, D12), outside `testpaths` so no `full_gate` ever collects it.
- **A restart policy for the proxy container.** Deferred in the spec; `--rm` and
  `--restart` are mutually exclusive in docker, so choosing one is a re-grill, not a
  line here.
- **`--image` and `--yolo` pass-through on the queue.** The spec says "re-raise when
  T015 lands". This is T015 landing; it is raised in the handoff, not settled here.
- **Filtering finer than one host.** Ports, paths, SNI: a different mechanism, and
  deliberately not this one.
