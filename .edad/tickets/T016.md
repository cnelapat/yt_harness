## Context

T002 built `--network` on the promise that `Internal: true` from docker means the agent
has no internet. It did, until T015: a forwarding proxy now sits on that network by
design, so the network being internal no longer backs the prompt's claim on its own
(D11), and every way the tier can be misconfigured — no route to the model, a dead
proxy, a stale image, a name collision, an expired token, a token never exported —
surfaces as the same 15-retry storm at 3am. That is why the spec says "probe it at plan
time" nine times rather than "document it".

And two invocations that look right are broken. `--sandbox docker` with no `--network`
runs `--network none`, where the CLI cannot reach the model at all (D10). `docker run
-e CLAUDE_CODE_OAUTH_TOKEN` with the variable unset passes nothing and raises no error,
so an operator who never minted a token gets a container with no credential and no
warning (D18).

## Goal

`validate_network` owns every docker-tier refusal, so the queue calling it once at plan
time (T013) and the session calling it from `preflight` get the same checks from one
function. The container is pointed at the proxy and has telemetry off, so the allowlist
is one entry. The prompt says what preflight has just measured. A standalone session
starts its own proxy and removes it; one that finds a proxy leaves it. The session log
says which half of `network_access: deny` was actually enforced.

Order of the refusals — cheapest first, and each one's message about its own cause:

1. `--network` without `--sandbox docker` — unchanged from T002.
2. `--sandbox docker` without `--network` — refused, saying that branch can never run a
   real agent (D10).
3. The network is not internal, or docker could not report on it — unchanged from T002.
4. An unconfigured throwaway container on the network reaches the internet — refused;
   and refused when that probe could not be run at all (D11).
5. **Dry-run stops here** (see Settled here).
6. `CLAUDE_CODE_OAUTH_TOKEN` is unset — refused, naming `claude setup-token` (D18).
7. The proxy permits a non-allowlisted host — refused; and refused when it could not be
   probed (D16).
8. `claude -p --max-turns 1` in the agent image, on the network, with the real token,
   does not exit 0 — refused; and refused when it could not be run (D16).

D18 sits after the isolation check rather than among the plain refusals: the token
gates only step 8, and placing it beside the probe that needs it leaves T002's three
existing refusal tests — which call `validate_network("docker", NAME)` with no token in
the environment — meaning what they meant. The spec's seam prose lists it earlier; the
difference is one instant container start before a "token unset" message, and it is
flagged in the handoff.

## Required interface

All in `edad/session.py`. Names are pinned by `tests/test_session_network.py`; read it
first. Every shell-out is a named module-level function returning `None` for "could not
run", the way `docker_network_internal` already does, so each answer can be stubbed
without a daemon — and so an unmeasured configuration is refused whatever the reason.

- `validate_network(sandbox, network, image=DEFAULT_IMAGE, dry_run=False) -> list[str]`
  The refusal chain above, in that order. Returns the names of the checks it *skipped*:
  empty unless `dry_run`, in which case the token check and both proxy probes. Existing
  callers ignore the return value; `cmd_run` prints it. Refusals are `Abort`, as today,
  and: D10's message contains `never run` and names `--network`; D11's contains `egress`;
  D18's contains `claude setup-token` and `CLAUDE_CODE_OAUTH_TOKEN`; D16's permit
  refusal includes the probe's output tail, because a dead proxy (403, 20s of retries)
  and a bad token (401, 3s) print the same `Failed to authenticate` prefix and are told
  apart by status, so the message must carry it.
- `docker_network_egress(network, image) -> bool | None`
  D11's probe: `docker run --rm --network <network> <image> python3 -c ...` attempting a
  raw-IP TCP connect (`1.1.1.1:443`, a few seconds' timeout) — no DNS anywhere, since an
  internal net has none and the probe must be instant in both directions (measured:
  `Network is unreachable` in 0.00s). `True` reached, `False` did not, `None` the
  container could not be run.
- `proxy_refuses(network, image) -> bool | None`
  D16's refusal half: a container on the network configured for the proxy sends `CONNECT
  example.com:443` to `proxy_url(network)`. `True` when the status is not `200`, `False`
  when it is, `None` when it could not connect or run.
- `permit_probe_argv(network, image) -> list[str]`
  Pure. `docker run --rm --network <network> -e CLAUDE_CODE_OAUTH_TOKEN -e
  HTTPS_PROXY=<proxy_url> -e HTTP_PROXY=<proxy_url> -e
  CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 <image> claude -p --max-turns 1 <prompt>`.
  The token as the bare `-e NAME` form: the value is never an element of this list.
- `proxy_permits(network, image) -> bool | None`
  D16's permit half: runs `permit_probe_argv` with the environment inherited (that is how
  the token crosses), `True` on exit 0, `False` otherwise, `None` when the subprocess
  could not be started or timed out. One trivial model turn; measured 4s.
- `agent_argv(prompt, workdir, sandbox, image, yolo, network=None)`
  Under docker with a network, adds `-e HTTPS_PROXY=<proxy_url(network)>`, `-e
  HTTP_PROXY=<same>` and `-e CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`. The token stays
  the bare `-e CLAUDE_CODE_OAUTH_TOKEN`; the frozen test sets the variable and asserts
  its value is in no element. Under docker with no network the argv is unchanged (the
  T002 test still pins `--network none`; D10 refuses that combination one step earlier,
  and this builder stays pure).
- `network_rule("docker", network=NAME)` — the named tier's sentence now says the only
  egress is the model API, via the proxy: contains `model API` and `proxy`, still
  contains the network name, `container name`, `internet` and `installs`, still not
  `--network none`. The T002 assertions are loose enough that no amendment is needed.
- `preflight(root, ticket, sandbox, dry_run, network=None, image=DEFAULT_IMAGE)` —
  gains `image` and passes `image` and `dry_run` through to `validate_network`. Six
  parameters trips `PLR0913`; silence it at the definition with the reason, as
  `agent_argv` does. `pyproject.toml` is out of scope.
- `SessionLog` gains `network: str | None = None` and `network_access: dict =
  field(default_factory=dict)`, after `sandbox`, both populated by `cmd_run`.
- `deny_enforcement(ticket, sandbox) -> dict[str, str]` — pure. `{"agent": ..., "verifier":
  ...}`: when the ticket's `kill_conditions.network_access` is not `deny`, both
  `"not requested"`; otherwise `agent` is `"enforced"` under docker and `"advisory"`
  otherwise, and `verifier` is always `"advisory"` — `run_commands()` sets
  `EDAD_NETWORK=deny`, a string a cooperating suite may honour, and nothing more (D8).
- `cmd_run` — imports `EgressError`, `ensure_egress_proxy`, `proxy_url` and
  `remove_egress_proxy` from `edad.egress` **by name into this module**, because the
  frozen test replaces `session.ensure_egress_proxy` and `session.remove_egress_proxy`.
  Under docker with a network and not dry-run, calls `ensure_egress_proxy(network)`
  **before `preflight`** (the proxy must exist before `validate_network` can probe it),
  translating `EgressError` to `Abort`; and removes it in a `finally` around everything
  that follows, **only if this call created it**. The `finally` is the substance: a
  refusal for any later reason — no lock, dirty tree — has already created a container,
  and teardown at the end of the session would leave it. The frozen test drives
  `cmd_run` with `repo_root`, `load_ticket` and `preflight` replaced, `preflight` raising
  `Abort`, and asserts the order `ensure, preflight, remove` when `ensure` returned
  `True` and `ensure, preflight` when it returned `False`.

## Settled here

**`--dry-run` under the docker tier runs the isolation check only, and says so.** Steps
1–4 run; the token check and both proxy probes are skipped; no proxy is started. A
dry-run exists to print the prompt, and with the probes it would start a container and
spend a model turn to do it. `validate_network` returns what it skipped and `cmd_run`
prints it on the `[dry-run]` line, so the operator is not told a network was validated
when half of the validation did not happen. The spec's deferred default, taken;
`test_a_dry_run_runs_the_isolation_check_only_and_says_so` pins it.
