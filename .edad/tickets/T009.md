## Context

T006's review found four behaviours its tests did not hold — those are T008's, and they
are defects in the tests. It also found three in the code, where the implementation
matches the ticket and the ticket is what is wrong. They are spec-level, so they are
amended and re-run rather than patched onto a branch.

**The final gate's timeout is the wrong quantity.** `final_gate_spec` takes
`max(command_timeout(ticket))` across every ticket on disk, which today is T006's 1800.
But `command_timeout_s` is a `kill_conditions` entry: it bounds how long an *agent* may
hang inside a session. The final gate is a test suite run by the controller with no agent
in it. Borrowing the agent's hang bound means a ticket that raised its own timeout — as
T006 did, for measured reasons that were entirely about the agent — silently changes how
long the night's last gate may take. Two quantities with one name is how a wall-clock
budget stops meaning anything: the operator sets a budget to bound the night, the queue
honours it, and then the epilogue runs on a bound nobody chose.

**The gate is unioned over tickets that are not in the run.** `final_gate_spec` globs
`.edad/tickets/*.md` and unions every `full_gate` it finds. Today all nine declare the
same two commands, so it is invisible; the first ticket to declare a third joins the
final gate of every run that does not include it. Taking the gate from the tickets rather
than a second list was right — D10's reason, that a gate kept beside the one the tickets
carry is a place for the two to disagree — but "the tickets" means the ones the run is
made of.

**A queue that stops on a merge git refused says nothing about it in the run log.** The
ticket is recorded `promoted, merge refused` and everything behind it `not_run`, with
`breaker: null`. The reason is real and the controller has it — `report_merge_refusal`
prints git's own words — but it goes to stdout only, and D9 exists because a scatter of
output the operator has to correlate by hand at 8am is what the run log replaced.

## Goal

The final gate is bounded by a quantity chosen for it. It is the union of the `full_gate`
commands of the tickets in *this run*. And the run log answers "why did this stop" for
every stop, not only for the two that are breakers.

## Before approving

Author the five tests named under `acceptance` into `tests/test_session_queue.py`, and
add the answer-free stubs that make their red provable (T007's D21/D22: a test that trips
a `NotImplementedError` produces ERROR, which is never detection, so the stub must return
a wrong answer rather than raise). `FINAL_GATE_TIMEOUT_S` does not exist yet and
`as_log()` has no `stopped_because` key; both need to be present and wrong at approval
time for the red proof to have teeth.

Author no others. A test for a later ticket is a `full_gate` failure this ticket's
baseline cannot absorb.

Both call sites are pinned, and the pins are T008's. `drive` replaces `final_gate` with a
one-argument stand-in, and `test_the_final_gate_runs_the_commands_the_spec_names` replaces
`final_gate_spec` with a one-argument lambda, so threading the ids through either turns 18
of this file's tests into `TypeError` — measured against a real implementation, not
predicted. Both stand-ins are therefore updated as part of authoring, which is what
`frozen` permits before approval and forbids after: four lines, every one of them arity.
T008's mutations were re-measured against the amended tests afterwards and are still
caught by exactly the node ids they name, so what changed is how the stand-ins are called
and not what any test asserts.

## Required interface

- `FINAL_GATE_TIMEOUT_S` — a module constant, the final gate's own per-command bound,
  with a comment saying what it is not. `final_gate_spec` stops calling `command_timeout`,
  which was that import's last use here, so the import goes with it: `ruff check .` is a
  `full_gate` command and fails on the stranded name.
- `final_gate_spec(root, ticket_ids)` — the union of `full_gate` across those ids, in
  first-seen order, deduplicated as it already is. The signature gains the ids rather
  than reading them off a `RunState`, so it stays as testable as it is now.
- `final_gate(root, ticket_ids)` — how the ids reach the spec, with `work_queue` passing
  the run's own. Named because it is the only caller, and leaving it at `final_gate(root)`
  is exactly what makes the bullet above unreachable. No default: a `ticket_ids` that can
  be omitted is a final gate that can run over no commands at all, and `all([])` being
  `True` is the vacuous pass T008's fourth mutation exists to catch.
- `RunState.as_log()` gains `stopped_because`: `None` on a clean drain, otherwise a short
  string naming the cause. A breaker sets it alongside `breaker` rather than instead of
  it — `breaker` stays the separate key D9 required, and `stopped_because` is the wider
  question that a merge refusal also answers.
- `work_one` records the merge refusal into `stopped_because` at the point it already
  calls `report_merge_refusal`, so the file and the screen carry the same sentence.

## Out of scope

- Whether the final gate should run at all after a breaker fires. It should, and it does:
  D10 holds that a measured claim beats a derived one, and the night going badly is when
  that matters most. What was wrong was the bound it ran under, which is D23. Skipping it
  would trade the measurement for the derivation exactly where the derivation is weakest.
- Reacting to a final gate failure beyond recording and reporting it — **D10**, unchanged.
- The run log's status vocabulary. Cosmetic, and T008 now pins the current names.
- Notification, cost budgets, parallelism — **D13**, still unenforced.
