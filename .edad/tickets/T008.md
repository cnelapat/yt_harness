## Context

T006 shipped `edad/session_queue.py` with all ten of its acceptance commands green, a
red proof on every one, and `mutation_proof: null`. That null is not an oversight — it
is the cost T007 priced. `cmd_approve` treats the two proofs as alternatives
(`edad/gate.py:1312`), and `prove_mutation_or_die` refuses unless acceptance is already
green against the code it characterizes. At T006's approval that code was the answer-free
stubs from `e502302`, so the mutation tier was out of reach and the red tier was the only
one available.

The red tier proves a test fails before the implementation exists. It does not prove the
test asserts anything about the implementation once it does. Four mutations to
`session_queue.py` were measured surviving all ten of T006's acceptance commands *and*
the full `python3 -m pytest -q` plus `ruff check .`:

- the breaker checked **after** the ticket it was meant to stop, rather than before;
- a ticket the breaker never reached logged `failed` rather than `not_run`;
- the first-cause-wins guard in `RunState.fail` deleted, so a second failure overwrites
  the first one's `failed` with `skipped` and re-attributes its dependents' reasons;
- `final_gate` running **no commands at all**, reporting `passed: True` because
  `all([])` is `True`.

The last is the sharpest: D10 exists to make one measured claim at the end of the night,
and nothing in T006 measured it. `drive` replaces `sq.final_gate` wholesale
(`tests/test_session_queue.py:179`), so the body never executes in any test.

## Goal

Those four behaviours are pinned by tests that die where they claim to pin. This is the
batch T007's out-of-scope section named and assigned — "their modules now exist and are
green at base, which makes them eligible for the mutation tier" — taken for T006, whose
module became eligible the moment it merged.

## Before approving

The four tests are authored already, appended to `tests/test_session_queue.py` under the
heading `T008: teeth for D7-D10`. They pass against the merged implementation, which is
what makes them correct, and each was measured failing under exactly one declared
mutation and no other. Commit them before running `approve`: the mutation is measured
against committed bytes while the lock hashes what is on disk, and `prove_mutation_or_die`
refuses an uncommitted frozen file rather than proving something about text the contract
does not cover.

`FOUR_INDEPENDENT` is new beside `CHAIN`, and it is the reason the second test can exist
at all. Failing any member of `CHAIN` skips every other member, so a run over it never
leaves a ticket the night did not get to — and a log that cannot produce `not_run` cannot
be asked whether it tells `not_run` from `failed`.

## What the agent does

Very little, and the ticket says so rather than inventing work. Acceptance is green
before iteration 1, so the session's first gate passes and it promotes. The artefact this
ticket produces is the `mutation_proof` block in `.edad/hashes/T008.json` — written by
`approve`, before any agent runs — plus the four committed tests. The session is what
carries that into an evidence record on the same path every other ticket uses.

## Amended after T009

D24 gave `final_gate_spec` the queued ticket ids, so the line the fourth mutation
quotes is now `final_gate_spec(root, ticket_ids)` and the old pattern matched nothing.
A `perl` substitution that matches nothing still exits 0, so it perturbs nothing, every
acceptance command passes, and `prove_mutation_or_die` refuses it as *survived* — a true
refusal with a misleading reason, since the blind spot it names is in the pattern rather
than in the test. The pattern is re-authored against the merged line and the proof
re-measured; what this ticket claims is unchanged.

## Out of scope

- Changing any behaviour of `session_queue.py`. Every mutation here is reverted with the
  throwaway worktree it ran in; nothing in `scope` is meant to differ at the end.
- The two defects the review found in the code rather than in its tests — the final
  gate's timeout taken from `max(command_timeout_s)` across every ticket, and
  `final_gate_spec` unioning `full_gate` over tickets that are not in the run. **T009**,
  which is red tier because both change behaviour and neither can be green at base.
- The run log's status vocabulary (`not_run`, `already done`, `promoted, merge refused`).
  Cosmetically inconsistent, and deliberately left alone: it is a shipped telemetry
  format, renaming it buys nothing, and these tests pin the names as they are.
- Teeth for T001-T005. Same batch, same tier, not blocking this.
