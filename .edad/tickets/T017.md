## Context

Every ticket before this one was implemented by an agent that could not run a test.
`--permission-mode acceptEdits` under `claude -p` has nobody to answer a permission
prompt, so every Bash call is denied — in the container and on the host alike. T014's
agent, in docker, ended its run with "I could not actually run the three acceptance
tests, the full frozen suite, or ruff myself"; T013's, on the host, "traced each of the
ten tests against the diff by hand". The gate was still the verdict, so nothing is
wrong with what merged. But a one-iteration pass on a small ticket hides a blind agent,
and a multi-iteration brownfield refactor will not.

The two tiers have different boundaries, so the fix is one rule per tier (D19). Inside
the container the boundary is the container — model-API-only egress, the worktree as
the only mount, and a `.git` file pointing at a host path so git inside cannot rewrite
anything — and `acceptEdits` there was a crippled agent, not a safeguard. On the host
there is no boundary, so the agent is allowed exactly the ticket's own gate commands.

Three things were measured before this ticket was written, and the interface below is
shaped by them:

- The CLI refuses `--dangerously-skip-permissions` as root ("cannot be used with
  root/sudo privileges"); `Dockerfile.agent` has no `USER` line. A `useradd` and `USER`
  after the installs fixes it: uid 1000, `HOME=/home/agent` writable, the CLI gets past
  the root check, and a bind-mounted worktree written from inside shows up on the host
  owned by the operator.
- `--allowedTools` is variadic. With the prompt after it, the CLI reports that no
  prompt was given. The prompt must precede the flag.
- With the prompt first and a comma-joined value, an unlisted `python3 -c` and `curl`
  are denied and a listed command runs. The operator's own `~/.claude/settings.json`
  allow rules also apply on the host — the allowlist is a floor, not a ceiling. That is
  a stated limit of the host tier, not something the builder can change.

And end to end, in the rebuilt image on the internal net through the real proxy: an
agent asked to run `python3 -m pytest` via its Bash tool did, and reported `1 passed`.

## Goal

Under `--sandbox docker` the agent argv carries `--dangerously-skip-permissions` and
nothing about permission modes, whatever `--yolo` says. On the host it carries
`--permission-mode acceptEdits` and one `--allowedTools` naming the ticket's own
commands, with the prompt ahead of it; `--yolo` on the host bypasses instead. The
session log says which. The agent image does not run as root.

## Required interface

All in `edad/session.py` except the last item. Names are pinned by
`tests/test_session_permissions.py`; read it first. The stubs are already in place and
return the wrong answer; replace their bodies.

- `allowed_tools(ticket) -> list[str]` — pure. For each command under `acceptance` then
  `full_gate`, in that order: `Bash(<command>)` exactly; and, when `pytest` is one of the
  command's whitespace-split tokens, `Bash(<tokens up to and including the first
  'pytest', space-joined>:*)` immediately after it. No duplicates — a pattern already
  emitted is not emitted again — and nothing wider: no bare `python3`, no `ruff`
  prefix. A ticket with neither list yields `[]`.
- `permissions(sandbox, yolo, ticket) -> dict` — pure. `{"mode": "bypass", "allowed":
  None}` when `sandbox == "docker"` or `yolo`; otherwise `{"mode": "allowlist",
  "allowed": allowed_tools(ticket)}`. `None` rather than `[]` under bypass, because
  bypass means everything and an empty list would read as nothing.
- `agent_argv(prompt, workdir, sandbox, image, yolo, network=None, allowed=None)` — the
  inner `claude` command becomes: under docker, or under `yolo`, `[*base,
  "--dangerously-skip-permissions", prompt]`; otherwise `[*base, prompt,
  "--permission-mode", "acceptEdits"]` followed by `["--allowedTools", ",".join(allowed)]`
  when `allowed` is non-empty. The docker wrapping around `inner` — `docker run`, the
  network, the mount, the bare `-e CLAUDE_CODE_OAUTH_TOKEN`, the proxy env — is
  unchanged; `tests/test_session_network.py` pins all of it and must stay green.
- `SessionLog` gains `permissions: dict = field(default_factory=dict)` immediately after
  `network_access`, populated where `network_access` is, with
  `permissions(args.sandbox, args.yolo, ticket)`.
- The iteration loop passes `allowed=allowed_tools(ticket)` to `agent_argv`.
- `Dockerfile.agent`: after the `pip install` line and before `WORKDIR`, create a
  non-root user with a home directory and switch to it — `RUN useradd --create-home
  --uid 1000 agent` then `USER agent`. Everything that needs root is above it. A short
  comment saying why (the CLI refuses the bypass flag as root, and inside this container
  the flag is the rule) — the file's existing comment style.

## Out of scope

- **Rebuilding the image.** The harness does not build images; the operator rebuilds
  `edad-agent:latest` after this merges, and the hand-run
  `test_the_agent_image_accepts_the_bypass_flag_as_its_user` in `docker_tests/` then
  proves what was built. This ticket's own night runs on the image as it is today.
- **`--yolo` on the queue.** Under docker bypass is now the rule, so the queue needs no
  flag; `--yolo` remains the standalone host-tier opt-in. `edad/session_queue.py` is
  untouched.
- **Making the host allowlist a ceiling.** The operator's own settings apply to a
  host-tier agent. Stated in the spec; not this ticket's to change.
- **Detecting whether the agent ran its checks.** The session log keeps the agent's
  output tail; this ticket's night is the measurement of whether the tail now says it
  ran pytest. What a detector should look for is decided after that, not before.
- **The `to-tickets` rule** that a gate command must not itself be a shell (`bash -c
  "..."` hands the agent a shell). A hand edit to the skill, landed alongside.
