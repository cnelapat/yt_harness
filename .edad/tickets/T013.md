## Context

The multi-ticket controller spawns each session as `python3 -m edad.session run <id>`
with no `--sandbox` and no `--network`, and the session defaults to `none`. So the
overnight run — the one path where nobody is watching the agent — is the one path that
never sandboxes. Its spec never uses the words; this was not decided against, it was
never raised.

With T015 and T016 merged, the docker tier is a tier that runs. What is left is
reaching it from the queue, and doing so without paying for it N times: the proxy
should be started once per night, and a misnamed network should cost seconds at ticket
0 rather than a night of instant aborts that the run log reports as "ran out of
tickets".

## Goal

`python3 -m edad.session_queue run T1 T2 --sandbox docker --network NAME` runs every
child under that tier. The queue defaults to `--sandbox none`, so a night nobody thought
about changes nothing (D4). Every child's recorded command states its tier, even when it
is the default, so two defaults in two files cannot drift apart (D6). The run log
carries `sandbox` and `network` at the top level, beside `run_branch`, so "did this
night run sandboxed" is a lookup (D4).

On a docker night the queue, after computing the plan and **before cutting the run
branch**: ensures the proxy, then calls `validate_network` once. A refusal there refuses
the run — no branch, no session spawned, exit 2 with the reason (D5). After the run,
in the same `finally` that writes the run log, it removes the proxy **only if it created
it** (D17). A `none` night asks docker nothing.

## Required interface

All in `edad/session_queue.py`. Names are pinned by `tests/test_session_queue.py`; read
it first, including the amended stand-ins.

- `build_parser()` — `run` gains `--sandbox {none,docker}` defaulting to `none` and
  `--network NAME` defaulting to `None`, with the session's own choices and help. Nothing
  else is threaded: `--image` and `--yolo` stay deferred.
- `session_argv(ticket_id, sandbox="none", network=None) -> list[str]` — always
  `[sys.executable, "-m", "edad.session", "run", <id>, "--sandbox", <tier>]`, and
  `"--network", <name>` appended exactly once when a name is given. `--sandbox` is emitted
  in every branch, default included.
- `run_session(root, ticket_id, sandbox="none", network=None) -> int` — passes both
  through to `session_argv`. `work_one` calls it with the tier `RunState` carries, always
  — never "only when not the default".
- `RunState(plan, tickets, budget_s=None, sandbox="none", network=None)` — carries both;
  `as_log()` adds `sandbox` and `network` as top-level keys, so `write_run_log` needs no
  change to put them beside `run_branch`.
- `run_queue(root, ticket_ids, budget_s=None, sandbox="none", network=None) -> int` —
  and `main()` passes the parsed flags through. Between `plan_run` and the branch cut,
  when `sandbox == "docker"`: `created = ensure_egress_proxy(network)` if a network was
  given, then `validate_network(sandbox, network)` — which is where a docker night with
  no network is refused, by T016's D10, without a proxy having been made. Both names are
  **imported into this module by name** (`from edad.session import Abort,
  validate_network`, `from edad.egress import EgressError, ensure_egress_proxy,
  remove_egress_proxy`), because the frozen test replaces `sq.validate_network`,
  `sq.ensure_egress_proxy` and `sq.remove_egress_proxy`. `Abort` and `EgressError` are
  translated to `Refusal` so `main()` prints and exits 2 as it does for every other
  refusal; the existing resumed-run summary on the way out is unchanged. `remove` runs in
  the `finally` beside `write_run_log`, only when `created`.

The ordering is the contract, and the frozen test observes it: the validation stand-in
records which branch root is on when called (`main`, not `edad/run-*`), and a refusal
leaves `session.ran == []`, no `edad/run-*` branch, and HEAD on `main`.

## Out of scope

- **The refusals themselves** — what `validate_network` checks: T016. The queue calls it
  and translates its `Abort`.
- **Per-ticket re-validation.** The child's own `preflight` re-runs `validate_network`
  anyway; a docker night probes N+1 times by construction, and that is the session being
  the session, not this ticket adding a subprocess to the hot loop.
- **The logless breaker** — D5's other half, T014. Once this ticket makes a refused
  network a plan-time refusal, the case T014 covers is the network that was fine at
  plan time and torn down at ticket 3.
- **`--image` and `--yolo` on the queue.** Deferred, unchanged.
- **Concurrency.** D13 of the controller spec is still unenforced; one proxy per night
  is already correct under a scheduler because `ensure` is once per `run_queue`.
