## Context

`preflight` runs before `SessionLog` is constructed, so a preflight refusal exits 2 with
no log. That is right for the session and was invisible to the queue: `RunState.fail`
with `session_log=None` *resets* the no-progress count — the breaker exists to stop a
night that is not running, and firing it on the absence of evidence would stop a night
on a guess.

With T016, preflight refuses for many more reasons, and one of them is the case this
ticket is for: a fixture network that was fine at plan time and was torn down at ticket
3 of 12. Every session after it aborts in preflight in seconds, writes no log, resets
the breaker, and the queue drains tickets 4–12 as instant `failed`s that the run log
reports as "ran out of tickets". The morning reads nine failures where there was one
environment problem.

## Goal

N consecutive sessions that produced no session log at all stop the night as an
environment failure, through a third breaker named distinctly from `no_progress` and
`wall_clock`, recorded in the run log as a breaker and not as a ticket failure. The
existing behaviour is kept exactly: a logless session still resets `no_commit_aborts`,
because a logless session is *distinguishable* evidence, not absent evidence, and the
two counters answer different questions. A session that did write a log resets the
logless count.

## Required interface

All in `edad/session_queue.py`; names pinned by `tests/test_session_queue.py`.

- `MAX_LOGLESS = MAX_NO_PROGRESS` — a module constant with a comment saying why it is
  the session's own threshold read one level up (see Settled here).
- `breaker_fired(*, no_commit_aborts, elapsed_s, budget_s=None, logless=0) -> str | None`
  — gains `logless`, keyword-only like the rest, and returns `"no_log"` when `logless >=
  MAX_LOGLESS`. Precedence among the three when more than one would fire is not pinned;
  keep `no_progress` first, since it is the older and better-understood signal.
- `RunState` gains `self.logless = 0`. `fail(ticket_id, session_log=None)`: when
  `session_log is None`, increment `logless` and reset `no_commit_aborts` (the existing
  branch, unchanged in effect); otherwise reset `logless` and do what it does today.
  `promote` resets both. `check_breaker` passes `logless=` through.
- The run log: a firing shows as `breaker: "no_log"`, `stopped_because` names it, the
  tickets it never reached are `not_run`, and the tickets that fired it are `failed`.
  `as_log`'s shape does not otherwise change.

`session_log=None` is what `read_new_log` returns both for "no file appeared" and for
"a file appeared and could not be parsed". Both count: neither is a session record the
queue can read, and the second is the same class of failure — the session did not run
to the point of writing what it always writes — with the added bad luck of a partial
file.

## Settled here

**N is `MAX_NO_PROGRESS`.** The spec left the count deferred with this as its default.
Taken, for the reason the no-progress breaker uses the same constant: one absorbs a
transient — a docker daemon hiccup, a lock refused because a human was mid-merge — and
two in a row is systematic. It is one constant, `MAX_LOGLESS`, aliased rather than
copied so that a future decision to raise one and not the other is a one-line edit with
a comment, and a decision to keep them together costs nothing.

## Out of scope

- **Making the queue read *why* a session was logless.** The refusal is on the child's
  stderr and the queue does not capture it. A breaker that quoted it would be better;
  it is also a channel the controller spec deliberately did not open (the exit code is
  the whole signal), and reopening it is a grill, not a line here.
- **Plan-time validation** — T013, which is what makes "torn down mid-night" the only
  way this breaker fires on a docker night.
- **The session writing a log for preflight refusals.** That would make every plain
  refusal a telemetry file and change what `SessionLog` means; the queue counting
  absence is the cheaper and more honest fix.
