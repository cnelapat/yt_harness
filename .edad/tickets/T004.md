## Context

`edad.session` runs one ticket and ends by printing *"Not merged — review and merge."*
That refusal keeps unreviewed code off a mainline and it is also the wall: `preflight`
wants a blocker's evidence record at the repo root, and `make_worktree` branches from
root HEAD, and only a merge satisfies both. So a chain of dependent tickets needs a
human awake between every pair, which is the whole cost of an otherwise unattended run.

## Goal

`python3 -m edad.session_queue run T00A T00B` cuts an integration branch from `main`,
checks it out in root, and works the queue: re-approve the ticket against that branch,
spawn its session, merge the promoted branch back as a fast-forward, move on. `main`
never moves. Because root HEAD *is* the run branch, `preflight` finds the blocker's
evidence and `make_worktree` branches from the blocker's code — with neither of them
modified.

The load-bearing property is that these merges are fast-forwards by construction: each
ticket branches from the run branch's then-current HEAD. Asserting `--ff-only` therefore
costs nothing and buys an alarm — a non-fast-forward means something ran concurrently or
a human intervened, and resolving it would put code on the branch that no `full_gate`
ever judged.

Re-approval is the other half. The approval lock pins a `full_gate_baseline`, and a
ticket may promote if it added no new failures — so a baseline taken before the run only
ever goes stale in the permissive direction. If T00A fixes a long-red test at 1am,
T00B's pre-run baseline still lists it, T00B's agent may break it again, and the ratchet
calls the regression pre-existing. Refreshing per ticket against the run branch is what
closes that. `refuse_silent_widening` already handles both directions: a shrinking
baseline passes silently, a growing one refuses.

## Required interface

Everything lives in `edad/session_queue.py`. `edad/queue.py` is not available — it
shadows the stdlib `queue` module.

- `Refusal(Exception)` — the run cannot start or cannot continue. Raised before, or
  instead of, doing damage.
- `session_argv(ticket_id) -> list[str]` — exactly
  `[sys.executable, "-m", "edad.session", "run", ticket_id]`. A pure argv builder, the
  shape `agent_argv` already established.
- `outcome_of(exit_code) -> str` — `"promoted"` for 0, `"failed"` otherwise.
- `check_reapprovable(root, ticket, drifted=None) -> None` — raises `Refusal` naming
  every drifted path. `drifted=None` means derive it from `check_freeze`, which already
  compares both the frozen hashes and the ticket's own bytes; the parameter exists so
  the refusal is testable without building an approval lock.
- `reapprove(root, ticket) -> None` — the named seam the tests replace. Calls
  `check_reapprovable` **first**, then approval. The order is the decision: approval
  rewrites the lock from the current tree, so running it over a drifted file would
  launder the drift into the contract.
- `run_session(root, ticket_id) -> int` — the named seam that spawns `session_argv` as
  a subprocess and returns its exit code.
- `discard_command(run_branch, ticket_branches) -> str` — a literal command naming the
  run branch and every `edad/t00N` branch.
- `run_queue(root, ticket_ids) -> int` — the driver. Cuts `edad/run-<ts>` from `main`,
  checks it out in root, and for each id in the order given: `reapprove`, `run_session`,
  and on a promoted outcome `git merge --ff-only` the ticket branch, recording the sha.
  A non-fast-forward stops the run with a non-zero return. Root is left on the run
  branch and the discard command is printed.

Spawning rather than importing is not stylistic. `gate.die()` raises a bare
`SystemExit(2)` from twenty-five sites that `session.main()` does not catch, so one bad
ticket in-process takes the night down; and a session holds the `edad.gate` it imported
at start, which is what makes the verifier the pre-session code. A controller that
imported once and looped would freeze that snapshot for the whole run, so the final
state of the run branch would never have been judged by its own gate.

## Out of scope

- Ordering the queue, refusing a cycle or an unsatisfiable blocker, reading evidence
  records, and resuming onto an existing run branch — **T005** (D1, D6, D12). This
  ticket runs the ids in the order given.
- Skip propagation, breakers, the run log and the final gate — **T006** (D7, D8, D9,
  D10). This ticket's tests replace the final-gate seam with `raising=False`, so it must
  not carry a stub for it.
- Parallel execution. D13 is unenforced and stays a design constraint: v1 is sequential,
  and the plan's independent set is recorded so a later scheduler is a change rather
  than a redesign. Do not build against parallelism, and do not hardcode against it.
- Merging anything to `main`, and removing per-ticket worktrees.

## Done when

Every command under `acceptance` exits 0, the frozen file hash is unchanged, and the
diff touches nothing outside `scope`.
