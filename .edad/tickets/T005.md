## Context

T004 runs the ids it is handed, in the order it is handed them. That is enough to prove
the integration branch works and not enough to walk away from: an operator who types
the tickets in the wrong order gets a run that fails on the first dependency, and one
who types a ticket whose blocker is nowhere gets the same failure several hours later.

It also cannot be re-invoked. A second run cuts a second branch from `main`, abandoning
the first night's work, and re-runs tickets that already passed.

## Goal

The queue is a plan, computed before anything executes. Ordering comes from the tickets'
own `blocked_by` rather than from argument order — a run manifest would put ordering in
a second place beside `blocked_by`, where the two can disagree. A cycle, or a blocker
that is neither queued nor already done, refuses the run in seconds rather than
discovering it hours in.

Doneness is the existence of `.edad/evidence/<id>.json`. `promote_evidence` is only ever
called on a promoted outcome, so the file existing already means promoted, and any field
read to answer the question is redundant. This matters because the records on disk are
not uniform. `mutation_proof` is absent from all three — the field postdates every
session run so far. And `passed_modulo_baseline` is `False` on T003, which passed
cleanly: `pre_existing_only` returns `False` whenever `commands_ok` is `True`
(`edad/gate.py:219`), so `False` there means *the baseline was not needed*, not *failed*.
A controller reading that key as a verdict marks a passing ticket not-done — a silent
wrong answer, strictly worse than a loud `KeyError`.

Re-invoking the exact same command resumes. No `--into <branch>` flag: it would be
correct, and it would be a flag to look up at exactly the moment the operator is annoyed
and half-awake.

## Required interface

Added to `edad/session_queue.py`.

- `Plan` — a dataclass with `order` (ticket ids to run, topologically sorted), `done`
  (already carrying evidence; not run and not re-approved) and `independent` (groups of
  mutually independent ids, recorded for D13 and asserted by nothing).
- `plan_run(tickets, requested, done) -> Plan` — pure. `tickets` maps id to the loaded
  ticket dict; `done` is a set of ids. Raises `Refusal` naming the ids involved on a
  cycle, and naming the unsatisfiable blocker — and only that blocker — when one is
  neither queued nor in `done`.
- `evidence_path(root, ticket_id) -> Path` and `is_done(root, ticket_id) -> bool`. The
  `done` set `run_queue` hands to `plan_run` is every id it is about to reason about that
  carries a record - the queued ids *and the blockers they name*. Probing only the queued
  ids refuses a run whose blocker is finished but was not re-typed, and reports that
  blocker as having no evidence record when it has one. A blocker satisfied this way is
  not a member of `Plan.done`, which is what the operator asked for and had already
  finished.
- `verdict(record) -> str` — `"passed"` or `"passed modulo baseline"`. Never reads
  `passed_modulo_baseline` as a verdict.
- `field_display(record, key) -> str` — `"not recorded"` when the key is absent or
  `None`, never `"no"`.
- `run_queue` gains its start rule: cut `edad/run-<ts>` only when root HEAD is `main`;
  when HEAD is already an `edad/run-*` branch, continue on it; anything else raises
  `Refusal` naming the branch it found. Done tickets are dropped from the queue and are
  never re-approved — re-approval rewrites `approved_at`, so doing it to a finished
  ticket weakens a provenance line for no gain.

## Out of scope

- The integration branch, the fast-forward merges, re-approval and the ending —
  **T004** (D2, D3, D4, D5, D11), merged before this starts.
- Skip propagation, breakers, the run log and the final gate — **T006**.
- Acting on `Plan.independent`. v1 is sequential (D13, unenforced). The set is computed
  and recorded so a later scheduler is a change rather than a redesign, and so the
  wall-clock that parallelism would have saved is measurable rather than assumed.
