## Context

`tests/test_acceptance_converter.py` is the oldest frozen file in this repo, and its
seven tests have never been shown to assert anything. T001 approved them under the red
tier at a time when `ytmp3/converter.py` did not exist, so every acceptance command
failed during collection: `ERROR`, exit 2. The module never loaded and no assertion in
the file was ever executed. What T001's lock records is that an import failed.

That is the exact evidence class D15 was written to refuse, and T001's lock predates it.
Worse, T001's single acceptance command names the whole file, so even the redness it did
record was pooled: the file went red as a unit and nothing distinguished a test with
assertions from one without. D22, merged in T010, now refuses that command shape
outright — T001 as written could not be approved today.

So these seven tests guard the only user-facing code in the repo — the converter — on the
strength of an import error. They may all be sound. Nothing on record says so.

## Goal

Prove each of the seven can fail, individually, by breaking the behaviour it claims to
pin and requiring *that* test to catch it. Seven mutations, one per test, each declaring
its own node id in `expects`. `unfired_expectations` holds every entry to firing, so a
mutation caught only by a sibling is refused rather than credited.

One mutation per test, and each killing only its own, is the author's discipline rather
than the gate's — the gate records collateral in `detected_by` and permits it. It is
worth holding to anyway: a mutation that kills five tests proves that *something* in the
file reacts, which is close to what whole-file redness already proved and well short of
knowing which test has teeth.

## Measured before approving

Every mutation was applied in a detached worktree and the whole file run against it. All
seven apply — the file's hash changes under each, which is the check that matters, because
a pattern matching nothing exits 0, perturbs nothing, and is then reported as the mutation
having *survived*, blaming the test for the pattern's own staleness. And each kills
exactly its declared test, no collateral, with `ruff check .` clean under all seven.

The outcome is on record here because it is the finding, not a formality: **none of the
seven tests is vacuous.** They were never verified, which is a different claim from being
wrong, and this ticket converts the first into the second's opposite.

## Why these seven mutations

Each targets the single behaviour its test names, and nothing a sibling also asserts.

- **`-vn` removed.** Only `test_command_is_pure_and_wellformed` asserts the flag is
  present. `test_convert_invokes_runner_with_built_command` compares the runner's argv to
  `build_ffmpeg_command`'s output, so both sides move together and it stays green — which
  is the point: that test pins the wiring, not the flag list.
- **Default suffix `.mp3` -> `.m4a`.** Only `test_output_path_defaults_to_input_stem`
  omits an explicit output path, so only it can see the default.
- **`check=True` -> `check=False`.** `test_convert_invokes_runner_with_built_command`
  asserts the kwarg. The two error-path tests raise from their fake runners regardless of
  it, so they are untouched.
- **The `is_file` guard deleted.** `test_missing_input_raises_before_invoking_runner`
  installs a runner that raises `AssertionError` if reached; with the guard gone it is
  reached. The other convert tests write a real file first, so the guard's presence is
  invisible to them.
- **`FFmpegNotFoundError` -> `ConversionError`, and the inverse.** Two mutations, one per
  error-path test. The classes are siblings under `ConverterError`, not parent and child,
  so neither `pytest.raises` accepts the other — which is what makes the pair separable
  at all.
- **Default runner resolution replaced by an early `return`.** `test_no_real_subprocess_by_default`
  is the only test that omits `runner`, and it monkeypatches `subprocess.run` to prove the
  default resolves at call time. An early return means its guard is never called.
  Deliberately *not* mutated into calling a different real `subprocess` attribute: that
  would attempt a genuine `ffmpeg` exec inside the mutation worktree, and a mutation
  should perturb the decision under test, not the sandbox.

## Widened scope

`ytmp3/converter.py` (D13). The agent does not need to modify it and is not asked to —
there is nothing to implement. It is in `scope` solely because every mutation's diff must
land inside `scope`, and all seven perturb that file.

The cost is real and is what this section exists to surface: naming it makes the
converter writable by the agent for the whole session, and the scope list alone reads as
ordinary. Approving this ticket is approving that widening. The kill conditions are set
tight against it — 40 diff lines, 3 iterations — because a correct run produces no diff
at all.

## What the agent does

Very little, and the ticket says so rather than inventing work. Acceptance is green before
iteration 1, so the session's first gate passes and it promotes. The artefact is the
`mutation_proof` block in `.edad/hashes/T011.json`, written by `approve` before any agent
runs; the session carries it into an evidence record on the same path every other ticket
uses.

## Out of scope

- **T001's own lock and evidence.** D19: the new bar binds new approvals only. T001's
  red proof is hash-anchored evidence of what was actually run, and editing it to look
  compliant destroys the property that makes it worth having. This ticket adds a second,
  stronger record beside it rather than rewriting the first.
- **Re-approving T001 with node-id commands.** Its acceptance block still names the whole
  file and still cannot pass D22. That only bites if someone re-approves it, and the seven
  node ids this ticket declares are the list they would need. Deliberately separate: a
  re-approval of an implemented ticket needs `--allow-passing` and has no red proof
  available, which is a different argument from this one.
- **T002's fifteen tests, and T003-T005.** Four more tickets of the same shape. T002 is
  the larger half of the 22 commands D22 was written about and should go next.
- **`--deselect` slipping past D22.** `pytest tests/ --deselect x.py::test_a` tokenises as
  naming a node id while running the whole directory. Found while reviewing T010, affects
  no ticket in the repo, and is a gate fix rather than a teeth ticket.
- **The stale-pattern misdiagnosis.** When a mutation pattern matches nothing the gate
  blames the test as a survivor instead of the pattern; `touched: []` is computed one
  block earlier and never read. This ticket works around it by verifying every pattern by
  hand, which is precisely the manual step that fix would remove.

## Done when

Every command under `acceptance` exits 0, the frozen file hash is unchanged, and the diff
touches nothing outside `scope`.
