## Context

`_supplies_detection` (`edad/gate.py:1102`) asks only whether a command contains a
`pytest` token. Node id or not, the answer is the same:

| command                                 | today | D22 wants  |
|-----------------------------------------|-------|------------|
| `pytest tests/test_x.py::test_y -q`     | True  | accept     |
| `pytest tests/test_x.py -q`             | True  | **refuse** |
| `pytest -q`                             | True  | **refuse** |

So a whole-file command discharges D15 on the strength of however many tests in the file
happen to carry assertions, and stays silent about the ones beside them. The author never
learns which were which. That is not a forward-looking gap: **T001** declares
`python3 -m pytest tests/test_acceptance_converter.py -q` (7 test functions) and **T002**
declares `python3 -m pytest tests/test_session_network.py -q` (15). Twenty-two frozen
tests whose vacuity was never examined, in this repo, today.

D22 is the last decision in the ledger carrying `verify:` that has no ticket and no
implementation. Everything else is discharged or marked `unenforced:` by design.

## Goal

Every pytest command in an acceptance set must name at least one node id. A command that
names none is refused at approve time, by name, on the union of offenders — a compliant
sibling beside it is not blamed, and an author who fixes one command per approve is not
made to.

The refusal is ordered *before* the existing detection refusals, and that ordering is the
substance rather than a detail: a whole-file command that produced a real `FAILED` passes
D15 cleanly, so if D22 ran second it would never be reached on exactly the input it
exists to catch.

## The red tier only, and why that is the decision rather than a shortcut

This refusal goes in `prove_red_or_die` and **not** in `prove_mutation_or_die`. Three
signals in the spec put D22 at the red tier: its `seam:` is `red-proof-gate`, its
`frozen:` is `tests/test_gate_red_proof.py`, and its rationale names D15 — the red tier's
teeth rule — as the thing a whole-file command satisfies while leaving tests unexamined.

There is a reason behind the three. The mutation tier already requires node ids, in
`expects:`, and `unfired_expectations` holds every one of them to firing. The command
string is not the only place a node id can appear there, so a whole-file command is
already pinned to the tests that must catch each perturbation. The red tier has no
`expects` — D22's own `rejected:` note explains why a second collection pass was refused
as the alternative — so for a red ticket the command string is the only place a node id
can be named, and a whole-file command is genuinely unexamined rather than merely terse.

Measured, not assumed: wiring the refusal into both tiers breaks 7 tests in
`tests/test_gate_mutation.py`, a file **T003** freezes and hashes and this ticket may not
write. Wiring it into the red tier alone breaks one test, in this ticket's own frozen
file. Both numbers come from a detached probe worktree carrying a correct implementation.

## What this ticket does about T001 and T002

Nothing, by decision. The refusal is approve-time, so their shipped evidence stands and
neither becomes retroactively invalid. What changes is that **neither can be re-approved
again** until its acceptance block enumerates node ids — 7 commands for T001, 15 for
T002.

That is the chosen outcome and not an oversight. Enumerating them here would drag two
shipped locks into a ticket about one refusal, and the refusal is what forces the work at
the moment it actually matters. The alternative of a grandfathering opt-out flag was
rejected: the spec's `rejected:` list is hostile to convenience flags in this area, and a
flag that exempts the precise case the rule exists to catch is the rule wearing a waiver.
T003–T009 already use node ids throughout and are unaffected.

## Pre-approval amendment to the frozen file

`test_error_only_red_proof_refuses_approval` covered the `ERROR` refusal twice: once with
a node-id command at exit 4, once with a whole-file command at exit 2. Its second half is
now D22's territory — that command refuses one rule earlier, for naming no node id — so
the half was removed and its case is pinned by `test_whole_file_pytest_command_refuses`
instead. Keeping it would have asserted the node-id refusal's wording inside a test about
teeth, and would have failed against a correct implementation.

Amended before `approve` hashed the file, which is when `frozen` permits it. The test
still pins the `ERROR`-is-not-`FAILED` distinction at exit 4, which is D15's real content,
and passes both before and after this change.

This changes `tests/test_gate_red_proof.py`, so **T007's `freeze_ok` reads False** from
here on. Nothing needs re-authoring: T007 is red tier — 9 `red_proof` entries,
`mutation_proof: null` — so it holds no mutation strings that could go stale, and it is
not re-approved by this ticket.

## Required interface

All in `edad/gate.py`.

- A predicate that answers whether a command names a pytest node id. Split on `shlex`
  with the same `ValueError` fallback `_supplies_detection` uses, and look for `::` in a
  token. Do **not** substring-match the raw command: `::` inside a `-k` expression or a
  quoted path is not a node-id selector, and tokenising is what `_supplies_detection`
  already does one line away.
- `_supplies_detection(command)` keeps its present meaning and signature. It answers
  "could this report a pytest FAILED", which is still what the D16 check and the
  `detected_by` recording need; the node-id question is a second, narrower predicate
  beside it. Folding the two would make a whole-file command look like a non-pytest
  command, and D16 would then refuse an all-whole-file set with "no command can supply
  the red proof" — blaming the author for the wrong thing.
- `prove_red_or_die(root, ticket, commands)` gains the refusal, after the timeout and
  all-pass refusals and **before** the D16 and per-command detection refusals, for the
  reason under **Goal**. Keep its return type and every existing refusal unchanged.
- Refuse on the union of offenders and name each one. The message must contain the
  substring `node id`, which the frozen test pins.
- `prove_mutation_or_die` is untouched. See the red-tier section.

## Out of scope

- The mutation tier. `expects:` already names node ids there and
  `unfired_expectations` already enforces them.
- Amending T001/T002 to node ids, and re-approving them. See above — two tickets of
  enumeration, deliberately not blocking this refusal.
- Migrating existing locks. D19: the new bar binds new approvals only. The red proofs
  T001–T005 recorded are hash-anchored evidence of what was actually run, and editing
  them to look compliant destroys the property that makes them worth having.
- Giving T001–T005's frozen tests teeth. Five tickets of mutation authoring, same tier as
  T008. Spec marks this *Owner: user*.
- The `survived` misdiagnosis when a `perl` mutation pattern goes stale: it matches
  nothing, exits 0, perturbs nothing, and `prove_mutation_or_die` blames the test rather
  than the pattern. `touched: []` is computed one block earlier and never read. A real
  two-line gap, and a candidate ticket of its own.

## Before approving

The tree is 173 passed, 2 failed, ruff clean, and the 2 are exactly this ticket's
acceptance commands. Each exits **1** and reports `FAILED` at its own node id inside the
frozen file; the census is `{1: 2}`.

No stubs were needed — as with T007, every name the tests import (`prove_red_or_die`,
`FakeRun`, `failed`, `refused`, `not_named`) resolves today, so the tests fail on
behaviour rather than on collection. D21's answer-free-stub requirement has nothing to
bite on here, and no `NotImplementedError` is introduced: that would produce pytest ERROR,
which `prove_red_or_die` refuses as detection.

`test_whole_file_pytest_command_refuses` was written so that it has teeth against the
unamended gate. Its fixture hands the whole-file command a genuine `FAILED` at *both*
frozen node ids, so D15 is satisfied and the only thing left to refuse on is the missing
node id. Had the fixture supplied an `ERROR` instead, today's D15 check would refuse it,
the test would pass against an unamended gate, and it would prove nothing about D22 — the
vacuous shape T007 caught twice during its own authoring.

Winnability was proved before anything was locked: a correct implementation applied in a
detached probe worktree takes the whole suite to 175 passed with `ruff check .` clean.
