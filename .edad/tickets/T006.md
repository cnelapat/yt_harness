## Context

After T004 and T005 the queue is ordered, refuses what it cannot do, and runs. It still
assumes the night goes well. One aborted ticket stops everything behind it including
work that never depended on it; a credential that expires at 3am burns every remaining
ticket into a false "failed"; and the only trace of any of it is a scatter of session
logs the operator has to correlate by hand at 8am.

## Goal

A failure is local. An aborted ticket is marked failed, everything transitively
reachable from it through `blocked_by` is skipped with that ticket named as the reason,
and independent tickets keep running. Stopping the queue on the first failure is safe,
simple, and spends the night on nothing when one ticket is merely hard.

Two breakers stop the queue for reasons that are not about the tickets at all. Two
consecutive aborts in which the agent committed nothing is `MAX_NO_PROGRESS`'s signature
one level up — an agent that exits non-zero and commits nothing is not failing the
ticket, it is not running — and it is detectable after the second one. A wall-clock
budget bounds the night the operator agreed to when they went to bed; it does not bound
the bill, and nothing here does.

The run writes one file the morning can be read from, and afterwards runs one full gate
on the run branch tip. That gate is redundant by derivation from the fast-forward
property — ticket N's gate already ran against every earlier ticket's merged code — and
it runs anyway, because this harness holds that a measured claim beats a derived one. If
it ever fails while every ticket promoted, the derivation is wrong somewhere; the run
log reports it and nothing else is designed.

## Required interface

Added to `edad/session_queue.py`, plus one line in `.gitignore`.

- `skip_reason(failed_id) -> str` — names the ticket that caused the skip.
- `no_commit_abort(session_log) -> bool` — True when a session log shows a non-promoted
  outcome and no iteration that made a commit. Reads the log the session already writes.
- `breaker_fired(no_commit_aborts, elapsed_s, budget_s) -> str | None` — pure, keyword
  arguments. `"no_progress"`, `"wall_clock"`, or `None`; `budget_s=None` means no
  wall-clock bound.
- `RunState(plan, tickets, budget_s=None)` — the fold. `fail(ticket_id,
  session_log=None)` records the failure and propagates skips; `skipped` maps a skipped
  id to its reason; `remaining()` lists what is still to run; `breaker` is `None` until
  one fires. `as_log()` returns the run-log payload, with `breaker` a **separate key**
  from `tickets` — a ticket the breaker never reached did not fail, and a log that
  conflated the two sends the operator to debug a ticket that never ran.
- `final_gate(root) -> dict` — the named seam the tests replace. Runs after the queue
  drains, on the run branch tip.
- `run_queue` writes `.edad/runs/<ts>.json`: per-ticket status, session-log path, merge
  sha, skip reason, timings, the breaker, and the final gate's result.
- `.gitignore` gains `.edad/runs/`. It is telemetry and joins `.edad/records/` and
  `.edad/sessions/` on the split that file already documents: telemetry is disposable
  and never committed, evidence is committed beside the code it verifies. Committing the
  run log onto the integration branch would break it.

## Out of scope

- The integration branch, the merges, re-approval and the ending — **T004**.
- Ordering, refusals, doneness and resume — **T005**, merged before this starts.
- Reacting to the final gate beyond recording it. By T004's fast-forward derivation a
  failure there cannot happen; if it does, the derivation is wrong and no automated
  response would be trustworthy. Report it loudly and stop.
- Notification. Nothing wakes the operator when a breaker fires at 3am; they read the
  run log in the morning. Not grilled, and the goal was wall-clock rather than latency.
- A cost or token budget, and measuring whether the queue is the *right* set of tickets.
