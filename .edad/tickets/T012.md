## Context

`prove_mutation_or_die` refuses a mutation command that times out and one that exits
non-zero (D9), then measures detection. It has no answer for the third way a mutation can
fail to apply: a command that **succeeds while matching nothing**.

A `perl -0pi -e 's/.../.../'` pattern whose source has since moved exits 0. It perturbs
nothing. The worktree stays at HEAD, where the acceptance commands pass exactly as they
did at base, so `detected` comes back empty and the survivor refusal (D7) fires:

```
the mutation '...' survived: no frozen test reported FAILED against it.
An approved blind spot is a licensed regression.
```

Every word of which is wrong about the cause. The frozen test is fine; the pattern is
stale. The author is sent to add teeth to a test that already has them, and the one fact
that would have said so — `touched`, the list of paths the mutation's diff changed — is
computed one block earlier, used for the scope check, and never read when empty.

This is not hypothetical. It was hit while hand-verifying T011's seven patterns, which is
why every one of them was checked for a hash change before the ticket was approved. That
manual step exists only because of this gap.

## Goal

When a mutation's diff is empty, refuse — naming the pattern as having matched nothing,
and before any acceptance command runs in the worktree.

The ordering carries the substance. Refusing after detection is measured reaches the same
verdict by the wrong route: D7 would already have fired, and a lock written from that run
would carry a measurement taken against unperturbed code. `touched` is the evidence and
it is available before the acceptance commands are launched, so the check belongs there —
beside D9's two refusals, which are ordered the same way and for the same reason.

The refusal must not say `survived`. That word *is* the misdiagnosis; a message that
keeps it while meaning something else has only changed which sentence is wrong.

## Required interface

All in `edad/gate.py`, inside `prove_mutation_or_die`'s per-mutation loop.

- After `touched = mutation_touched_paths(wt)` and **before** the stray-scope check and
  the acceptance run, refuse when `touched` is empty.
- Reuse `touched`. Do not add a second git call, and do not compare the worktree's HEAD
  to the root's: that answers the same question more expensively and still misses a
  mutation that edits a file and reverts it, which `git diff --name-only` reports as
  empty and which is equally not a perturbation.
- The message names the command, says it changed no files, and points at the pattern
  rather than the test. It must contain the substring `changed no files`, which the
  frozen test pins, and must not contain `survived`.
- D9's two refusals, the stray-scope refusal, and the survivor refusal all keep their
  present wording and order. This adds a branch; it rewrites none.
- `mutation_touched_paths` keeps its signature. `tests/test_gate_mutation.py` monkeypatches
  it through `install(monkeypatch, run, touched=...)`, so the stand-in already supports an
  empty list and needs no amendment — unlike T009's case, nothing here pins a new arity.

## Out of scope

- The `deferred:` entry about `expects` node ids going stale on a test rename. Related in
  spirit — both are staleness the gate reports as something else — but it is a different
  signal (the frozen hash) and a different fix.
- Validating mutation patterns at author time, before approve runs them. It would need the
  gate to parse `perl`/`sed` expressions, and the check this ticket adds already catches
  the same class at the only moment the answer is certain.
- `--deselect` slipping past D22's node-id check. Unrelated tier, found in the same
  review, and a separate gate fix.

## Before approving

The tree is 175 passed, 2 failed, ruff clean, and the 2 are exactly this ticket's
acceptance commands. Each exits **1** and reports `FAILED` at its own node id inside the
frozen file; the census is `{1: 2}`.

The two tests are red against the **existing implementation**, not because anything is
absent: `prove_mutation_or_die`, `mutation_touched_paths` and `install`'s `touched=`
parameter all resolve today. The first test fails because the refusal it asserts does not
exist and the survivor refusal fires instead; the second because the acceptance command
does reach the worktree. No stub is introduced, and D21 has nothing to bite on.

Winnability was proved before anything was locked: the empty-`touched` refusal applied in
a detached probe worktree takes the whole suite to 177 passed with `ruff check .` clean.

No existing mutation pattern goes stale from this change. `edad/gate.py` is perturbed by
no ticket's `mutation:` block — T008's patterns target `edad/session_queue.py` and T011's
target `ytmp3/converter.py`, checked by parsing both blocks rather than by grep, since
both tickets mention `gate.py` in prose.

Editing `tests/test_gate_mutation.py` sets **T003's `freeze_ok` to False**. T003 is red
tier — 25 `red_proof` entries, `mutation_proof: null` — so it holds no mutation strings
that could go stale, and this ticket does not re-approve it. Same posture T010 took
toward T007.
