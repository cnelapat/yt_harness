## Context

`--sandbox docker` is all-or-nothing. `agent_argv()` hardcodes `--network none`,
so a ticket whose work needs a service — a database, a fake API — cannot be run
sandboxed at all, and the only way to give the agent that service today is to
drop the sandbox entirely and hand it the open internet with it.

The missing tier is narrow: reach these containers, reach nothing else. Docker
already models it as an internal network. What the harness must not do is take
the operator's word for it. `network_rule()`'s docstring is explicit that the
prompt must never assert a constraint nothing enforces, and a network named
`isolated` that happens to have a gateway would make every later prompt a lie.

## Goal

`python3 -m edad.session run T00N --sandbox docker --network NAME` runs the
agent container attached to NAME, after the session has confirmed with docker
that NAME exists and is internal. The agent is told the truth: it can reach
services on that network by container name, and it still has no internet.

Without `--network`, nothing changes: the container runs `--network none`.

## Required interface

- `docker_network_internal(name: str) -> str | None`
  The probe, and the only thing here that shells out. Runs
  `docker network inspect <name> --format '{{.Internal}}'` and returns its
  stripped stdout, or `None` when the command fails for any reason — no such
  network, no daemon, no docker. A named module-level function because the
  frozen test replaces it; the refusal logic must never call subprocess itself.
- `validate_network(sandbox: str, network: str | None) -> None`
  Returns for the default tier (`network is None`) without calling the probe.
  Raises `Abort` when `network` is given with a sandbox other than `docker`,
  with a message naming `--sandbox docker`. Otherwise calls the probe and
  raises `Abort` naming the network when it answers `None` (missing) or
  anything other than `"true"` (exists, not internal). Called from
  `preflight()`, which gains the network argument.
- `agent_argv(prompt, workdir, sandbox, image, yolo, network=None)`
  Keyword-defaulted last, so existing positional calls are unchanged. Under
  `--sandbox docker` it emits `--network <name>` when a name is given and
  `--network none` when it is not — exactly one `--network` flag either way.
  Under any other sandbox it emits no docker command at all, as now.

  Six parameters trips `PLR0913` (max 5), and `edad/session.py` is the only
  file in scope, so silence it at the definition with `# noqa: PLR0913` and a
  comment giving the reason: this is a pure argv builder whose parameters are
  independent inputs rather than a function that has grown too many jobs. Do
  not restructure the signature — the frozen test pins these call shapes, and
  do not touch `pyproject.toml`, which is out of scope.
- `network_rule(sandbox, cont_indent="", network=None) -> str`
  Third branch when `sandbox == "docker"` and `network` is not None. Its text
  must name the network, say services on it are reachable by container name,
  and say there is no internet egress, so no installs or downloads. It must not
  contain `--network none`, which would be false. The `cont_indent` join
  applies to this branch as it does to the other two — the rule is interpolated
  into a numbered list in `initial_prompt()`.
- `build_parser() -> argparse.ArgumentParser`
  The parser `main()` builds, extracted so the wiring is testable without
  spawning a process. `run` gains `--network NAME`, defaulting to `None`, with
  a required value.

## Out of scope

The verifier. `run_commands()` in `edad/gate.py` runs the acceptance and
full_gate commands on the host, and this ticket does not change that or touch
that file. A test database serving the agent on an internal network is expected
to publish a host port for the verifier to reach; joining the verifier to the
network is a separate decision nobody has made.

Also out of scope: creating or tearing down the network (the operator supplies
an existing one), any per-ticket network declaration in ticket frontmatter, and
egress filtering finer than docker's internal flag.
